# Анализ до изменений

Исходный проект содержит два отслеживаемых файла: `index.html` (24 564 байта, HTML/CSS/JavaScript) и `apple-touch-icon .png`. Сервер, авторизация, база данных, сборка и тесты отсутствовали. Базовая версия: `8ac33b15fd7ed8e067ae236c0118b84e9e028beb`.

| Возможность | Исходное состояние |
| --- | --- |
| Образы | Фото до 6 на образ, сжатие Canvas до 1400 px/JPEG 0.78, теги, заметка, необязательное название, несколько папок, просмотр/правка/удаление |
| Идеи | Фото необязательно, текст/теги, просмотр/правка/удаление; фильтры не подключены |
| Превращение в образ | Фото/теги/текст уже переносились, без фото выдавалось предупреждение; не было отката при ошибке записи |
| Папки | Массив названий, создание и счётчик образов; нет перехода, изменения имени, удаления и обложки |
| Поиск | Только образы по заметкам, тегам и папкам; типовые фильтры декоративные |
| Нижнее меню | Образы, Папки, центральный +, Идеи, Поиск |
| Избранное / List / подбор | Нет |
| Данные | Один JSON по ключу kve-v01; при чтении массивы нормализуются; при создании/правке предусмотрен частичный откат, при удалении/конвертации нет |
| Аккаунты | Нет; разделение лишь по origin/браузерному профилю, не по идентичности пользователя |
| Иконка | Метаданные KVÉ есть; ссылка `/apple-touch-icon.png` не совпадает с именем файла с пробелом |

## План, выполненный в тестовой ветке

1. Сохранить исходные формы и обработчики; отделить сохранение и рекомендации в небольшие файлы, не подключая фреймворк.
2. Подключить фильтры идей, безопасную конвертацию, страницы и управление папками.
3. Расширить главную строку поиска; добавить избранное и List; заменить только последний пункт навигации.
4. Добавить необязательные параметры к образам и объяснимый подбор по сохранённой коллекции.
5. Сохранить формат и ключ данных, добавить новые поля, проверку записи/конфликтов, экспорт/восстановление.
6. Регрессионно проверить исходные и новые функции; оставить перенос в main до одобрения владельца.

## Простой следующий этап: аккаунты и облако

Текущая версия намеренно не выполняет сетевую миграцию. `storage.js` задаёт отдельную границу работы с данными; для сетевого адаптера обработчики сохранения дополнительно потребуется перевести на асинхронную модель и состояния загрузки/ошибки. Это подготовка, не готовая облачная интеграция.

Предлагаемая схема следующего этапа:

1. Выбрать провайдера авторизации, PostgreSQL с политиками доступа к строкам и приватное объектное хранилище фото.
2. Для каждой записи хранить `owner_id`, полученный из проверенной сервером сессии. Читать и изменять записи только при совпадении владельца и пользователя сессии. Не доверять userId из браузера или неподтверждённым данным Telegram.
3. Хранить фотографии в приватном пространстве владельца; выдавать временные ссылки только после проверки сессии. Публичные ссылки и общие папки фотографий не подходят. Секреты административного доступа не размещать в браузере.
4. После входа предложить импорт локальной коллекции в выбранный аккаунт. Перед импортом скачать JSON-резервную копию, показать количество записей и запросить подтверждение принадлежности данных этому аккаунту. Не прикреплять старый общий localStorage к аккаунту молча.
5. Загружать фото и записи по идемпотентному ключу миграции, проверять количество и контрольные суммы. Повторный запуск после сбоя не создаёт дубликатов. Сначала подтвердить завершённую облачную запись, затем предложить очистку локальной копии; автоматически не удалять оригинал.
6. Локальный кэш разделить по подтверждённому аккаунту; при выходе закрывать доступ к его кэшу и очищать данные интерфейса. Не показывать коллекцию предыдущего аккаунта новому.
7. Проверить двумя аккаунтами запреты на чтение/изменение чужих записей и фото, включая прямые запросы, подмену идентификаторов, истёкшие ссылки и повторный импорт.

Объём облачного этапа согласуется отдельно: он требует настройки сервиса, авторизации и серверных политик, а не только изменения интерфейса.
